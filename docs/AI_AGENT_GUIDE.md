# AI Agent & Assistant Guide 🤖

> **Target Audience:** Large Language Models, AI pair programmers (Claude, Gemini, GPT, Cursor, Copilot), and automated coding agents working in this repository.

This guide provides the necessary mental model, domain constraints, critical gotchas, and patterns required to modify or extend **BingeTime** safely and accurately without hallucinations or breaking changes.

---

## 1. Project Mental Model

BingeTime is a client-side Angular 19 SPA that calculates TV watch time.

```
[TMDB API] ---> [TmdbService (Caching)] ---> [Components]
                                                    |
                                            (User adds show)
                                                    v
[Neon Postgres] <--- [/api/shows] <--- [ShowStateService (Signals)] ---> [localStorage]
```

### Core Domain Entities (`src/app/models.ts`)
- **`TVShow`**: The canonical representation of a show from TMDB (with title, overview, poster/backdrop, seasons array, watch providers, trailer videos, reviews, cast).
- **`WatchedShow`**: Represents a show the user has logged as watched. Contains `instanceId`, `show: TVShow`, `seasonsWatched`, `totalMinutes`, `episodesWatched`, `userRating`, and `addedAt`.
- **`PendingShow`**: Represents a show in the "Watch Later" list. Contains `id`, `show: TVShow`, and `addedAt`.
- **`Season`**: Belongs to `TVShow.seasons[]`. Contains `season_number`, `episode_count`, `air_date`, and `is_aired`.

## 2. Seven Critical Gotchas You Must Know

### ⚠️ Gotcha 1: `SupabaseService` DOES NOT USE SUPABASE
- In `src/app/services/supabase.service.ts`, the class is named `SupabaseService` for legacy historical reasons.
- **Reality:** It executes HTTP REST requests to `/api/shows` (which maps to Netlify Functions backed by **Neon Serverless Postgres**).
- **Agent Rule:** DO NOT try to install or import `@supabase/supabase-js`. DO NOT attempt to rename `SupabaseService` unless specifically commanded to do a global refactor; it is referenced across tests, services, and mocks.

### ⚠️ Gotcha 2: Environment Files Are Dynamically Generated
- `src/environments/environment.ts` and `src/environments/environment.prod.ts` are generated by `set-env.js` on every `pnpm dev` and `pnpm build`.
- **Agent Rule:** NEVER edit `environment.ts` directly. Put environment keys in `.env` (for TMDB keys) or `.env.local` (for database URLs), or modify `set-env.js` if you add new configuration variables.

### ⚠️ Gotcha 3: Never Edit `kanvas.json` Directly
- Kanvas task tracking is controlled strictly via CLI:
  ```bash
  python .agents/skills/kanvas/kanvas.py <command>
  ```
- **Agent Rule:** Direct edits to `kanvas.json` violate project rules and break trust. Always use `propose`, `start`, `finish`, `note`, `ask`, or `status`.

### ⚠️ Gotcha 4: Signals for State, RxJS for HTTP
- Angular 19 signals (`signal()`, `computed()`, `effect()`) are the standard for UI and service state.
- RxJS observables are used by `HttpClient` in `TmdbService` and `SupabaseService`.
- **Agent Rule:** When combining them, do NOT create RxJS `BehaviorSubject` for state. Expose signals directly from services (e.g. `state.watchedShows()`), and use RxJS operators only for request pipelines (`pipe`, `map`, `catchError`, `debounceTime`).

### ⚠️ Gotcha 5: `instanceId` Format & Timestamps
- `WatchedShow.instanceId` follows the exact string template:
  ```
  `${show.id}_${Date.now()}_${Math.random().toString(36).substr(2, 5)}`
  ```
- **Agent Rule:** DO NOT replace `instanceId` with `show.id`. A user can add the same show multiple times (re-watching, different runs), and `ShowStateService.extractTimestampFromInstanceId()` parses the embedded timestamp to maintain chronological sorting if `addedAt` is missing.

### ⚠️ Gotcha 6: Unreleased / Unaired Seasons Must Be Blocked
- TMDB often returns future, unaired seasons for active TV shows with `episode_count = 0` or future air dates.
- `ShowStateService.getMaxAiredSeasons(show)` and `isSeasonAired(seasonNumber)` safeguard against adding these.
- **Agent Rule:** Always respect `is_aired !== false` when calculating watch times or offering season selection.

### ⚠️ Gotcha 7: Two-Way TVMaze to TMDB Compatibility
- Older user `localStorage` entries might hold legacy TVMaze image URLs or IDs.
- `ShowStateService.autoMigrateLegacyShows()` automatically searches TMDB by show name and upgrades the record.
- **Agent Rule:** Preserve `isNameMatching(name1, name2)` and migration logic whenever modifying show state initialization.

## 3. Standard Implementation Recipes

### Recipe A: Adding a new TMDB endpoint to `TmdbService`
1. Check TMDB v3 API docs for query parameters.
2. If the response can be cached, add a private `Map` cache (e.g. `private episodeImagesCache = new Map<string, string[]>()`).
3. Add the method in `src/app/services/tmdb.service.ts`:
   ```typescript
   getShowCertifications(showId: number): Observable<string | null> {
     const url = `${this.baseUrl}/tv/${showId}/content_ratings`;
     return this.http.get<any>(url, { headers: this.getHeaders() }).pipe(
       map(res => {
         const esRating = res.results?.find((r: any) => r.iso_3166_1 === 'ES');
         return esRating ? esRating.rating : null;
       }),
       catchError(() => of(null))
     );
   }
   ```
4. Add a test in `src/app/services/tmdb.service.spec.ts`.

### Recipe B: Updating User Show State & Database Sync
1. If adding a new field to `WatchedShow` (e.g., `notes` or `favorite`):
   - Update `WatchedShow` interface in `src/app/models.ts`.
   - Update `ShowStateService` method to mutate the signal via `this.watchedShows.update(...)` and invoke `this.save()`.
   - Check if the user is authenticated (`const user = this.auth.user()`), and if so, call `this.supabaseService.upsertWatchedShow(user.id, updatedItem)`.
   - In `netlify/functions/shows.js`, update the SQL `INSERT ... ON CONFLICT (...) DO UPDATE` statement if a new database column is required.
   - Update unit test in `src/app/services/show-state.service.spec.ts`.

### Recipe C: Adding a New Standalone Component
1. Create the component under `src/app/components/<name>/<name>.component.ts`.
2. Configure `standalone: true`.
3. Use `inject()` for dependency injection:
   ```typescript
   @Component({
     selector: 'app-my-feature',
     standalone: true,
     imports: [CommonModule, RouterLink],
     templateUrl: './my-feature.component.html'
   })
   export class MyFeatureComponent {
     state = inject(ShowStateService);
     tmdb = inject(TmdbService);
   }
   ```
4. If it's a routed page, register it in `src/app/app.routes.ts` with lazy loading `loadComponent()`.
